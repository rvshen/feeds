Halo，你好，见字如面，我是林卿 👋

从2026年5月9日第一次让AI帮我正儿八经干活儿，我在Claude Code和Codex，这两个AI工具上跑了大概430次对话，手打了1300多条消息，产出超过60万字的正文内容，沉淀了14个生效的SKILL、3个AI智能体，跑了三个客户项目和我自己的全部内容业务，消耗了40多亿Token。

所以我想把自己实践出来的AI协作经验全部开源。

01.碰到陌生任务，先让AI反向梳理需求。

08.AI产出验收三段式：

先给整体结论，再列编号纠偏清单，最后抽查执行情况。

09.不满意的时候，不要亲自改稿，而是把“为什么不好”翻译成可复用的规则反喂回去。

10.高质量返修可以写成：

具体问题 + 为什么有问题 + 只修改什么 + 什么保持不变 + 怎么样才算修改好。

12.我的AI协作铁律

12.1.禁止覆盖、移动、删除任何已有文件，只允许新建文件；

同名的加版本号v2、v3。

12.2.禁止跳读、禁止用搜索摘要代替通读，读不完就分批读。

12.3.不确定的直接写“不确定”，资料不足写“资料不足，无法判断”，素材没覆盖到的宁可留空标注“素材缺口”，禁止编造数据、案例、来源和客户反馈等。

12.5.所有SKILL的真身放在桌面的SKILL文件夹里，生效目录只放软链接。

一份内容一个源头，改一处处处生效，不会出现两份副本各改各的。

12.6.客户项目的SKILL和我个人的SKILL完全拆分，不允许合并、互相调用。

12.7.布置项目任务先说“请只在这个文件夹里工作”，别的文件夹不许碰。

12.8.除非我明确要求覆盖，否则保留原始资料和历史版本，新建带日期或者版本号的新文件。

保留过程不是怕误删，而是为了保留学习链路：

原始资料 -> AI初稿 -> 人工修改稿 -> 终稿 -> 修改规律 -> 反哺SKILL……

13.SKILL不是写出来的，是从跑通的对话/任务里蒸馏出来的。

14.进化系统：

让AI越写越像我

第一步，语料库工程

第二步，修改规律飞轮：

AI出稿 -> 我手动修改 -> 差异回流成规律 -> 规律更新SKILL -> 下一篇AI稿件更像我 -> 我需要改的地方越来越少……
