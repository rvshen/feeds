关于AI、自媒体和做生意的一些思考。

Halo，你好，见字如面，我是林卿 👋

国庆假期的时候，我去参加了生财有术南昌和赣州的线下聚会。

回来之后，陆陆续续整理了一些学习笔记，也顺便把自己过去一段时间关于AI、自媒体、SKILL和商业经营的一些思考重新梳理了一遍，整理在这儿，存档记录一下。

有些来自聚会里的交流，有些是顺着这些话题，我自己的拓展延伸……

观点不一定都成熟，也不一定适用于所有人，但至少是我现在比较真实的想法，所以Mark一下。

01.我不太看好从头到尾都是AI数字人口播的视频。

现阶段，如果想通过AI做视频自媒体，我觉得有一种内容生产方式比较值得尝试：

AI数字人＋真实视频素材、录屏、动效等混剪。

*截图内容只是大概展示一下“

AI数字人＋真实视频素材、录屏、动效等混剪”大概是什么样的效果，并不代表我截图的这几个账号是AI数字人！

单纯用AI数字人从头讲到尾，确实可以省去不少真人出镜和拍摄的成本，但问题也比较明显，尤其是AI数字人长时间持续出镜之后，用户很容易就会意识到这是一条AI视频。

如果视频脚本再比较模板化、画面又没什么变化，叙述节奏也比较机械化的话，那整条视频就会显得单调、缺乏真实感……

当然，我也不是觉得用户会天然排斥AI生成的内容，毕竟真正影响用户观看的，还是内容和用户有没有关系、有没有信息量或者说价值，以及画面呈现怎么样，是不是足够自然、有趣……

所以，相比于让AI数字人从头讲到尾，我更倾向于把AI数字人当成视频生产过程里的一个组件，而不是整条视频的全部。

比如：

开篇先通过AI数字人引入话题，接着切换到真实产品画面、软件录屏、代码运行、案例截图、AI生成视频等素材。

讲到关键操作的时候，就直接展示操作过程；

讲到实际效果的时候，就直接展示效果对比；

需要衔接内容的时候，再适当穿插数字人口播……

让不同类型的素材发挥对应的作用：

AI数字人：

降低真人出镜和拍摄成本，承担口播和内容衔接；

真实视频素材：

提供具体场景，增加画面的自然感和代入感；

录屏和操作演示：

直观展示过程、功能和效果；

案例截图和数据：

补充证据，提高内容的信息密度；

剪辑和动效：

突出重点，优化内容节奏和观看体验……

尤其是知识型内容，就很适合用这种方式来呈现。

所以，我觉得未来成熟的AI视频生产工作流，不一定是追求100%AI生成，

而是根据不同内容的特点，把最适合的生产方式组合起来。

当然，最后还是要回到内容效果和生产效率上，在保证内容质量的前提下，能不能用更少的人、更低的成本、更短的生产周期，持续产出有价值的内容？

02.AI自媒体的商业价值，不一定和粉丝量成正比。

有些做AI相关内容的自媒体账号，即便只有几十、几百个粉丝，也已经可以接到小几百元的商业合作。

当然，这只是在交流里了解到的个别案例，不代表只要做AI账号，几十个粉丝就能接广告。

而造成这种情况的原因可能是现在有大量AI产品和工具需要进行市场推广、产品介绍和用户教育。

对于一部分品牌商家来说，相比于账号拥有多少粉丝，TA们可能更关心创作者的内容生产能力、产品理解能力和用户教育能力，比如：

这个账号能不能精准触达目标用户？

创作者是不是真的懂AI产品？

能不能把产品功能、使用场景和实际价值讲清楚？

能不能持续产出有质量的内容？

过往内容有没有不错的传播和转化表现？……

所以，小账号不代表没有商业价值。

在某些垂直场景下，1000个精准用户的商业价值，确实可能高于1万个泛用户。

03.如果AI已经让内容生产越来越简单，那么创作者之间的竞争优势究竟是什么？

以前，愿意出镜、懂拍摄、会剪辑，本身就有一定门槛。

现在通过AI数字人、配音、录屏、素材混剪等方式，即便不真人出镜，也能完成一条相对完整的视频。

当越来越多人都能低成本生产内容，单纯的生产能力就可能越来越不值钱，反而是内容选题、专业理解、真实经验、个人判断，以及对目标用户需求的洞察……

这些软实力会变得更加重要。

AI可以帮我们更便宜地生产内容，但不一定能帮我们生产出真正“有价值”的内容。

这也是我准备持续投入精力研究的方向。

04.AI写得越来越好，但为什么还是不像自己？

这是我之前使用AI进行内容创作的时候，经常会碰到的一个问题。

有时候，AI生成的文章确实挑不出什么明显的问题，结构很完整，逻辑也通顺，语言表达也没什么毛病……

但读完之后，总觉得差点意思，说不上哪里不对，就是感觉不像我自己写出来的。

后来我逐渐意识到，我给AI的要求，和我期待它做到的事情，可能并不匹配。

如果我只告诉AI：

“帮我写一篇关于XXX的文章。”

但希望它知道我为什么想写这个话题、认同什么、不认同什么，还要按照我的表达风格完整写出来……

很显然不现实！

所以，

想让AI写出来的内容越来越像自己，就得让AI真正了解自己，以及知道我究竟想表达什么。

比如给AI持续投喂那些真正影响自己思考和表达的信息：

我的成长和职业经历、做过哪些项目、有过哪些成功和失败的案例；

我长期关注什么、擅长什么、相信什么、反对什么；

我看待一个问题的时候，习惯从哪些角度思考；

我通常怎么判断一件事情值不值得做；

我喜欢什么样的内容结构、语言风格和表达节奏；

有哪些词汇、句式和表达方式，是我基本不会使用的；

过去写过哪些文章，哪些内容是自己比较满意的，哪些内容实际表现比较好……

这些信息积累起来之后，就可以逐渐形成自己的角色卡、人设卡、人生地图、观点库、案例库、表达风格库和内容素材库。

当然，也不是把所有个人信息毫无筛选地交给AI，重点应该是沉淀那些真正有助于创作、而且适合提供的信息。

至于让AI知道我究竟想表达什么，只需要投喂清晰的写作背景、目标读者、写作目标、具体的观点/经历/案例之类的就够啦。

05.比持续投喂AI更重要的，是

让AI理解我为什么和怎么修改内容

。

光让AI了解自己过去写过什么，我觉得还是不够。

因为过去的内容只能告诉AI“我曾经怎么表达”，不一定能告诉AI，我为什么这样表达。

所以我现在更关注的是，能不能让AI从自己每一次修改内容的过程里，持续学习自己的判断标准。

一篇文章从创作到发布，通常会经历：

AI生成初稿、人工修改、最终定稿、正式发布、数据反馈等环节，我们可以把这些过程完整保留下来，再让AI进行对照分析和复盘，比如：

我为什么删掉了这一段？

我为什么觉得这个开篇不够好？

我为什么把某个词换掉了？

为什么有些句子虽然没有语病，但我还是选择重写？

哪些问题是AI经常犯的？

哪些修改只是我的个人表达习惯？

哪些修改涉及逻辑和观点判断？

哪些内容最终获得了不错的用户反馈？

哪些内容虽然AI觉得很好，但实际发布之后效果却很一般？……

再让AI尝试总结其中的规律，并反过来更新自己的内容创作规则，逐渐形成这样一套机制：

AI生成初稿 -> 人工修改 -> 正式发布 -> 真实数据反馈 -> 复盘初稿和终稿差异 -> 复盘内容表现 -> 提炼规律 -> 更新创作规则 -> 下一次继续使用……

当然，单篇内容的数据表现可能受到选题、发布时间、平台流量等多种因素影响，不能简单把数据好坏归因于某个表达方式，但如果长期积累、对比和验证，这套机制就有机会帮助我们逐渐识别哪些方法真正有效。

06.

封装SKILL的时候，先别急着让AI写SKILL.md。

我觉得不少人在使用AI的时候，容易陷入一个误区：

明明自己都还没有想清楚要做什么、怎么做，就已经开始要求AI生成一整套解决方案了，最后得到的可能就只是一个看起来完整，但实际上完全用不了，或者达不到预期的结果。

做SKILL也是一样的！

所以，在做SKILL之前，要先把实际的诉求、工作流程什么梳理清楚，至少需要明确：

这个SKILL到底解决什么问题？

什么场景下需要调用？

需要提供哪些输入材料？

执行过程应该分为哪些步骤？

每个步骤有什么要求和判断标准？

最终需要输出什么内容？

怎么判断输出结果是合格的？

哪些错误绝对不能出现？

有没有已经验证有效的参考案例？……

如果这些问题自己暂时还没有想清楚的话，其实也可以让AI帮忙一起梳理，比如：

我是谁

现在想做一件什么样的事情

背景是什么

我需要给你提供哪些信息？

你会怎么帮忙完成？

最终会输出哪些内容？

如果比较复杂的话，我就会让AI用

苏格拉底式问诊

的方式，通过一轮轮的提问，帮忙梳理清楚，比如：

我是谁

现在想做一件什么样的事情

背景是什么

我现在的想法/解决方案/工作流程是什么

现在有哪些相关信息/资料

先不要提供解决方案，先对我进行一次苏格拉底式问诊，通过提问的方式，帮我梳理清楚我真正的诉求等，然后再思考最佳解决方案。

请遵守这些规则：

01.每次只问一个问题，根据我的回答决定下一问，不要提前给我一整套问卷；

02.优先区分我说的是可验证的事实、对事实的解释、价值判断，还是我希望实现的目标；

03.检查内容是否含糊、我默认了哪些前提、证据来自哪里、有没有相反解释，以及结论成立或不成立分别意味着什么；

04.每次提问前，用一句话说明上一条回答让你更新了什么判断；

05.只问可能改变结论的问题，信息足够时立刻停止。

这个方法不仅适用于做SKILL，也适用于很多其他的陌生AI任务。

07.做SKILL，不要什么都默认从0开始。

明确自己的诉求之后，其实没必要从零开始做SKILL。

可以先去GitHub之类的平台上看看，有没有成熟的SKILL可以直接用，或者有没有类似的SKILL可以学习借鉴等。

有的话，就直接用或者在它的基础上修改迭代一下；

没有的话，也可以看看有没有可以学习借鉴的。

所以，对于做SKILL，我觉得更合理的顺序应该是：

明确需求 -> 检索成熟方案 -> 评估能否复用 -> 根据实际业务调整 -> 没有合适方案再自行封装。

08.SKILL第一次封装完成，只是开始。

想长期稳定使用，还需要把它放到真实的任务里调用测试，看看哪些步骤能正常完成、哪些地方容易遗漏、哪些输出不符合预期……

再根据实际结果，逐步修改，直到它能比较稳定地完成目标任务为止。

09.SKILL越来越多以后，管理SKILL有时候比封装SKILL更麻烦。

这也是我自己在使用过程里已经碰到的问题，比如：

我之前封装了小红书账号分析、爆款内容分析、爆款内容创作、爆款仿写等不同的SKILL，它们之间存在一些的语义重叠。

有时候，我只是想仿写爆款，AI却同步调用了爆款分析SKILL，把原本正常的任务带偏了。

所以，后来我给SKILL增加了更严格的触发规则：

请把这个SKILL的名称修改成：

把这个SKILL的触发条件修改成：

只有明确提及调用这个SKILL的时候才触发，其他情况下不主动调用。

10.做生意之前，

先想清楚有哪些钱可以赚，自己准备赚什么钱，以及这些钱具体怎么赚。

11.对于中小品牌商家来说，在生意还没有跑通之前，

复购、用户LIV价值就是个伪命题。

12.

碰到有效的红利，就应该抓住红利、往死里干，集中资源把它做透。

不过有效红利是需要经过真实业务验证的，比如：

这个渠道是不是真的有机会？

这个内容模型能不能持续产生有效动销？

这个SKU有没有稳定需求？

这个账号模型能不能重复跑通？

投入更多资源之后，能不能继续保持合理的利润空间？……

如果已经经过验证，且还有机会的话，那就果断 All in。

13.增长之外，我会越来越关注成本结构和经营效率。

以前研究自媒体和生意的时候，大家可能更习惯关注怎么增长、怎么获得更多流量、更多GMV……

但我觉得，随着业务逐渐成熟，另一个问题同样重要，即：

在不牺牲必要质量的前提下，能不能用更低的成本完成同样的结果？

比如：

内容生产成本还能不能降低？

获客成本还有没有优化空间？

供应链成本能不能进一步压缩？

相同规模的业务，能不能通过更合理的流程减少重复劳动？

团队能不能借助AI和自动化工具，提高单位人力产出？

同一套内容、商品和供应链能力，能不能被更多账号和店铺复用？……

这也是为什么我觉得多账号、多店铺、矩阵化经营真正值得研究的地方，并不是单纯追求数量，而是能不能让已经有的经营能力被重复利用。

如果一套团队、内容和供应链能力，可以在不明显增加管理成本的情况下支撑更多业务，那么单位成本就有机会降低。

但如果只是不断增加账号和店铺，却没有相应的组织能力和运营效率，反而可能导致成本上升、管理混乱、利润下降。

所以，规模本身不是优势，

能够被低成本复制、并且持续产生利润的经营能力，才可能形成真正的优势。

14.写在最后

这次整理的内容看起来比较分散，但整理完之后，我发现它们其实存在一些共通的逻辑。

第一，先想清楚自己真正要解决什么问题，再考虑使用什么工具和方法。

工具、方法和机会，本身都不是目的，它们是否值得使用，最终还是取决于能不能解决实际问题、创造真实价值。

第二，先通过实践验证方法，再考虑怎么复制和规模化。

第三，能交给工具和系统重复执行的工作，就尽可能沉淀下来；

真正需要自己做的判断，不要轻易外包。

这也是我最近使用AI过程里感受越来越明显的一点。

比如在用AI创作内容的时候，我更希望AI能够帮助我降低生产成本、提高工作效率，让我有更多精力去学习、实践、思考，以及形成真正属于自己的判断。

毕竟，当所有人都能够使用AI生产出结构完整、逻辑通顺、看起来很正确的内容之后，那些千篇一律的正确表达，可能反而会越来越不值得被关注。

而一个人真实的经历、独特的观察、明确的立场，以及愿意为自己的观点负责的态度，才更可能构成难以被复制的差异。

这也是为什么，我越来越认同：

只有偏见，才会被偏爱。
